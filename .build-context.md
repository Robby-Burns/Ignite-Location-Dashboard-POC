# Atlas Guides — Durable Build Context

## Project Overview
- **Project**: Ignite Facility Operational Decision Agent POC
- **Objective**: Operational decision support agent translating facility data into understandable findings, trend analysis, positive indicators, prioritized watch items, and data-grounded recommendations for facility leaders and CIO review.
- **Scope**: Focused strictly on a single flagship POC facility (**Ignite Medical Resort Oak Brook** - `ignite-oak-brook`).
- **Specification Contract**: `Ignite_Facility_Operational_Decision_Agent_POC_Spec_v0.1.md` (and `Atlas-Guides-V2.2/spec.md`)
- **Governing Protocol**: Atlas Guides V2.2 (`kernel.md`, `build-plan.md`, `current-loop.md`)

## Deployment & Runtime Infrastructure
- **Target Deployment Platform**: Railway / Cloud Container
- **Target Production Database**: Neon PostgreSQL (Serverless)
  - Connection Config: `DATABASE_URL` or `NEON_DATABASE_URL` via `.env`
  - Python PostgreSQL Driver: `pg8000` (pure-Python, fully compatible across Windows ARM64, x86_64, Linux/Railway containers)
  - Engine & Session: SQLAlchemy 2.0 (`create_engine`, `SessionFactory`) with clean URL normalization (`urllib.parse`)
  - Seeding CLI: `python -m src.db.seed` (creates `facilities` and `daily_facility_snapshots` tables, seeds 180 snapshot records for Oak Brook across 6 scenarios)
  - Local Dev/Test Fallback: `sqlite:///./ignite_facility.db` (auto-fallback when testing or if DB URL is unset)
- **AI / LLM Configuration**:
  - Providers: OpenRouter (unified API for Gemini, Claude, GPT, DeepSeek, Llama), Google Gemini (native REST with `x-goog-api-key`), OpenAI
  - Model Selection: Configurable via `LLM_MODEL` in `.env` (e.g. `google/gemini-2.0-flash-001`, `anthropic/claude-3.5-haiku`, `openai/gpt-4o-mini`, `gemini-2.0-flash`)
  - Offline Safety: Transparent `AI_ANALYSIS_UNAVAILABLE` fallback when no API key is provided
- **Backend Framework**: Python 3.12+ / FastAPI / Pydantic v2 / Uvicorn / Pytest (59 unit/integration tests)
- **Frontend Target**: React / Vite (configured for `npm.cmd run build`)

## Architecture Components

### 1. Data Models (`src/models/facility.py`)
Typed Pydantic structures for all 8 required operational domains:
- `CensusData`: Current census, capacity, occupancy percentage, available beds, previous day/week census, budgeted target.
- `AdmissionsDischargesData`: Daily admissions/discharges, pending pipeline, net flow, rolling 7-day totals.
- `LengthOfStayData`: Average/target LOS, short-stay vs long-stay breakdown, outlier counts.
- `TherapyData`: Scheduled vs delivered minutes, treatment completion %, weekly goal attainment %, therapy holds, mobility gain index.
- `StaffingData`: HPPD actual vs budgeted target, RN/LPN/CNA hours, call-ins, open shifts, overtime, agency %.
- `PayerAuthData`: Payer mix distribution, expiring authorizations (48h/72h), pending re-authorizations, active appeals.
- `HospitalityData`: Dining score, cleanliness & comfort score, guest NPS, open service requests, average resolution turnaround.
- `HospitalTransferData`: 30-day unplanned transfers, 30-day readmission %, weekly acute transfers, categorized transfer reasons.
- `DailyFacilitySnapshot`, `FacilityHistoricalSeries`, `FacilityDataset`.

### 2. Synthetic Data Generator & Seeder (`src/data/synthetic_generator.py`, `src/db/seed.py`)
- Generates 30-day historical time-series for the single POC facility (`ignite-oak-brook`).
- 6 operational scenarios: `baseline`, `staffing_stress`, `auth_cliff`, `hospital_transfer_spike`, `therapy_disruption`, `high_census_strain` (30 days $\times$ 6 scenarios = 180 snapshot records).

### 3. Data Loader (`src/data/loader.py`)
- Caching, scenario dataset loading, JSON validation, and typed error handling (`DatasetUnavailableError`, `DatasetValidationError`).

### 4. Database Layer (`src/db/database.py`, `src/db/models.py`, `src/db/seed.py`)
- Pure-Python driver initialization, connection pooling, table schema creation (`init_db`), and ORM persistence tables (`FacilityRecord`, `DailySnapshotRecord`).

### 5. Mock Domo MCP Layer (`src/mcp/`)
- In-process MCP server and typed client exposing 5 operational tools (`domo_list_facilities`, `domo_get_facility_snapshot`, `domo_get_facility_history`, `domo_get_domain_metrics`, `domo_get_connection_status`).

### 6. Analytics & Calculations Engine (`src/analytics/`)
- Deterministic calculations across all 8 operational domains, variance vs targets, and cross-departmental correlation detector (`calculate_facility_metrics`).

### 7. Decision Agent & LLM Client (`src/agent/`)
- `LLMClient`: Multi-provider async client supporting Gemini, OpenAI, custom endpoints, configurable `LLM_MODEL`, and grounded dynamic reasoning synthesis with verifiable execution receipts.
- `FacilityStateAgent`: Operational state decision agent producing `FacilityStateAnalysis` (AC-2.1.1, AC-2.1.2) with `NumericalGroundingReconciler` to eliminate hallucinated numbers.
